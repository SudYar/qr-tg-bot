# Архитектура проекта

## Обзор

Проект следует модульной архитектуре с четким разделением ответственности. Код организован в соответствии с принципами чистой архитектуры и лучшими практиками Python.

## Структура проекта

```
qr-tg-bot/
├── bot/                          # Основной пакет приложения
│   ├── __init__.py              # Инициализация пакета, версия
│   ├── bot.py                   # Главный класс бота (QRCheckBot)
│   ├── config.py                # Управление конфигурацией
│   │
│   ├── handlers/                # Слой обработчиков
│   │   ├── message_handlers.py  # Обработка входящих сообщений
│   │   └── callback_handlers.py # Обработка callback-запросов
│   │
│   ├── services/                # Бизнес-логика и внешние сервисы
│   │   ├── qr_scanner.py        # Сканирование QR-кодов
│   │   └── receipt_api.py       # Взаимодействие с API чеков
│   │
│   ├── utils/                   # Утилиты и вспомогательные функции
│   │   ├── message_formatter.py # Форматирование сообщений
│   │   └── keyboard_factory.py  # Фабрика inline-клавиатур
│   │
│   └── models/                  # Модели данных
│       └── user_selection.py    # Модель выбора пользователей
│
├── run.py                       # Точка входа (локальный запуск)
├── index.py                     # Обработчик webhook (serverless)
├── main.py                      # Legacy-обертка для совместимости
└── interface.py                 # Legacy-модуль интерфейса
```

## Слои приложения

### 1. Конфигурация (`bot/config.py`)

**Назначение**: Централизованное управление настройками приложения

**Ключевые компоненты**:
- `Config` - класс конфигурации
- Загрузка из переменных окружения через `.env`
- Обратная совместимость с `config.py`
- Валидация обязательных параметров

**Переменные окружения**:
- `BOT_TOKEN` - токен Telegram бота
- `CHEK_TOKEN` - токен API Proverkacheka
- `CHEK_URL` - URL API Proverkacheka
- `API_TIMEOUT` - таймаут для API запросов

### 2. Модели (`bot/models/`)

**Назначение**: Определение структур данных и бизнес-логики

#### UserSelection (`user_selection.py`)
- Управление выбором пользователей для каждого товара
- Операции добавления/удаления выборов
- Подсчет общего количества выбранных товаров

### 3. Сервисы (`bot/services/`)

**Назначение**: Бизнес-логика и взаимодействие с внешними API

#### QRScanner (`qr_scanner.py`)
- Сканирование QR-кодов с изображений
- Использует OpenCV для распознавания
- Обработка ошибок при сканировании

#### ReceiptAPI (`receipt_api.py`)
- Взаимодействие с API Proverkacheka
- Два метода получения данных:
  - По QR-коду (строка)
  - По файлу изображения
- Парсинг ответа API в DataFrame
- Обработка ошибок сети и API

### 4. Утилиты (`bot/utils/`)

**Назначение**: Вспомогательные функции общего назначения

#### MessageFormatter (`message_formatter.py`)
- **Создание сообщений**: Формирование текста со списком товаров
- **Парсинг сообщений**: Извлечение данных из текста сообщений
- **Регулярные выражения**: Паттерны для поиска данных
- **Расчет сумм**: Подсчет итоговой суммы для каждого пользователя

**Основные методы**:
- `create_receipt_message()` - создание сообщения из DataFrame
- `parse_message_lines()` - разбор на пары строк
- `extract_quantity()` - извлечение количества
- `extract_users()` - извлечение пользователей
- `calculate_user_totals()` - расчет итоговых сумм
- `format_totals_message()` - форматирование итогового сообщения

#### KeyboardFactory (`keyboard_factory.py`)
- **Фабрика клавиатур**: Создание inline-кнопок
- **Управление callback**: Создание и парсинг callback-данных
- **Динамические кнопки**: Изменение кнопок в зависимости от состояния

**Основные методы**:
- `create_product_selection_keyboard()` - создание клавиатуры выбора
- `create_callback_data()` - формирование JSON для callback
- `parse_callback_data()` - парсинг callback-данных

### 5. Обработчики (`bot/handlers/`)

**Назначение**: Обработка входящих событий от Telegram

#### MessageHandlers (`message_handlers.py`)
Обрабатывает входящие сообщения:
- `/start`, `/help` - приветствие
- Фото с QR-кодом - сканирование и обработка
- Неизвестные команды - информационное сообщение

**Процесс обработки фото**:
1. Загрузка изображения от пользователя
2. Сканирование QR-кода (QRScanner)
3. Получение данных чека (ReceiptAPI)
4. Форматирование ответа (MessageFormatter)
5. Создание клавиатуры (KeyboardFactory)
6. Отправка сообщения пользователю

#### CallbackHandlers (`callback_handlers.py`)
Обрабатывает нажатия на inline-кнопки:
- Выбор товара (`choice`)
- Подсчет суммы (`summ`)

**Процесс обработки выбора**:
1. Парсинг callback-данных
2. Извлечение текущего состояния из сообщения
3. Обновление выбора пользователя (UserSelection)
4. Форматирование нового текста
5. Обновление сообщения и клавиатуры

### 6. Главный класс (`bot/bot.py`)

**QRCheckBot** - центральный класс приложения

**Ответственность**:
- Инициализация бота и компонентов
- Регистрация обработчиков
- Управление режимами работы (polling/webhook)

**Методы**:
- `__init__()` - инициализация и валидация конфигурации
- `_register_handlers()` - регистрация обработчиков сообщений
- `run()` - запуск в режиме polling
- `process_update()` - обработка webhook-событий

## Принципы проектирования

### 1. Разделение ответственности (Separation of Concerns)
Каждый модуль отвечает за одну область функциональности:
- Сервисы - внешние интеграции
- Обработчики - логика взаимодействия с пользователем
- Утилиты - вспомогательные функции
- Модели - структуры данных

### 2. Слабая связанность (Loose Coupling)
Модули независимы друг от друга:
- Сервисы не знают о Telegram API
- Утилиты не зависят от конкретных сервисов
- Легко заменить или модифицировать компоненты

### 3. Высокая связность (High Cohesion)
Связанная функциональность сгруппирована:
- Все методы работы с сообщениями в одном модуле
- Вся логика клавиатур в одном месте

### 4. Принцип единственной ответственности (Single Responsibility)
Каждый класс имеет одну причину для изменения:
- `QRScanner` - только сканирование
- `ReceiptAPI` - только API
- `MessageFormatter` - только форматирование

### 5. Открыт для расширения, закрыт для модификации (Open/Closed)
- Легко добавить новые обработчики
- Легко добавить новые типы кнопок
- Не нужно менять существующий код

## Паттерны проектирования

### 1. Factory (Фабрика)
`KeyboardFactory` создает объекты клавиатур по запросу

### 2. Strategy (Стратегия)
Различные стратегии получения данных чека:
- По QR-коду
- По файлу изображения

### 3. Template Method (Шаблонный метод)
Общий процесс обработки сообщений с вариациями

## Потоки данных

### Сценарий 1: Сканирование чека

```
Пользователь → Фото
    ↓
MessageHandler.handle_photo()
    ↓
QRScanner.scan_qr_code() → данные QR
    ↓
ReceiptAPI.get_receipt_from_qr() → DataFrame
    ↓
MessageFormatter.create_receipt_message() → текст
    ↓
KeyboardFactory.create_product_selection_keyboard() → клавиатура
    ↓
bot.send_message() → Пользователь
```

### Сценарий 2: Выбор товара

```
Пользователь → Нажатие кнопки
    ↓
CallbackHandler.handle_callback_query()
    ↓
KeyboardFactory.parse_callback_data() → данные
    ↓
MessageFormatter.parse_message_lines() → текущее состояние
    ↓
UserSelection.add_user() / remove_user() → новое состояние
    ↓
MessageFormatter.format_selection_line() → новый текст
    ↓
KeyboardFactory.create_keyboard_from_message() → новая клавиатура
    ↓
bot.edit_message_text() → Пользователь
```

### Сценарий 3: Подсчет суммы

```
Пользователь → Нажатие "Просуммировать"
    ↓
CallbackHandler._handle_sum_calculation()
    ↓
MessageFormatter.calculate_user_totals() → суммы
    ↓
MessageFormatter.format_totals_message() → текст
    ↓
bot.reply_to() → Пользователь
```

## Обработка ошибок

### Уровни обработки

1. **Сервисный уровень**: 
   - Специализированные исключения (`ReceiptAPIError`)
   - Логирование ошибок

2. **Уровень обработчиков**:
   - Try-catch блоки
   - Пользовательские сообщения об ошибках

3. **Уровень приложения**:
   - Валидация конфигурации
   - Graceful degradation

## Расширяемость

### Добавление новой команды

```python
# В bot/handlers/message_handlers.py
def handle_new_command(self, message: Message) -> None:
    self.bot.send_message(message.chat.id, "Новая команда!")

# В bot/bot.py
@self.bot.message_handler(commands=['new'])
def handle_new(message):
    self.message_handlers.handle_new_command(message)
```

### Добавление нового типа кнопки

```python
# В bot/utils/keyboard_factory.py
ACTION_NEW = "new_action"

# В bot/handlers/callback_handlers.py
elif method == KeyboardFactory.ACTION_NEW:
    self._handle_new_action(call)
```
